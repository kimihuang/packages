# CODEBUDDY.md

This file provides guidance to CodeBuddy Code when working with code in this repository.

## Overview

`ipi_monitor` is a GPL-2.0 Linux kernel module that implements **per-core health monitoring via a ring of per-core hrtimers** ("环状双向互监", 方案 A' in the design docs).

Each online CPU runs a **pinned hardirq `hrtimer`** (`HRTIMER_MODE_*_PINNED_HARD`). The timer callback:
1. increments its own per-cpu `atomic64_t heartbeat_counter` (self-heartbeat proving "this core can service interrupts"), and
2. monitors the ring's **predecessor and successor** cores by reading their counters and comparing against a local snapshot.

Every core is therefore watched by two neighbors (no single monitor point of failure), and the heartbeat signal is generated by each core's own hardirq — it no longer depends on thread scheduling or IPIs.

This detects **L2 (hard deadlock: IRQs/preemption disabled)** and **L4 (core hardware failure)**. It does NOT detect L1 soft deadlocks (the hrtimer still fires with IRQs enabled); the sibling `per-core-thread_monitor` package ("方案 B") covers that case.

## Build

No standalone Makefile — it is a kernel module built via kbuild (`Kbuild` → `obj-m += ipi_monitor.o`).

A configured, pre-built kernel tree exists at `out/quantum_qemu_debug/build/linux-6.1/` (with `Module.symvers`). Cross-compiler is at `tools/arm-gnu-toolchain-13.3.rel1-x86_64-aarch64-none-linux-gnu/bin/`. Build and verify with:

```bash
make -C <repo>/out/quantum_qemu_debug/build/linux-6.1 ARCH=arm64 \
     CROSS_COMPILE=<repo>/tools/arm-gnu-toolchain-13.3.rel1-x86_64-aarch64-none-linux-gnu/bin/aarch64-none-linux-gnu- \
     M=$PWD W=1 modules
```

(Use `clean` to remove generated `.o`/`.ko`/`Module.symvers` artifacts after building.)

Buildroot integration: menuconfig under `Board options -> Quantum Board Packages -> ipi-monitor` (`Kconfig` symbol `IPI_MONITOR`, depends on `ARM64 && SMP`).

No lint/test suite; validation is manual on-target:
- Load: `insmod ipi_monitor.ko [check_interval_ms=500] [stall_threshold=3] ...`
- Status: `cat /proc/ipi_monitor`
- Unload: `rmmod ipi_monitor`

## Architecture

Two source files (plus `Kbuild`/`Kconfig`):

- `ipi_monitor.h` — `struct ipi_monitor_cpu_state`, `enum ipi_monitor_cpu_status`, `IPI_MONITOR_NR_PEERS`.
- `ipi_monitor.c` — hrtimer callback, ring-neighbor helpers, hotplug callbacks, procfs, report workqueue.

### Core data structure (`struct ipi_monitor_cpu_state`)

Per-cpu, allocated with `DEFINE_PER_CPU` to avoid cache-line false sharing:

- `heartbeat_counter` (`atomic64_t`) — written only by this core's hrtimer (`atomic64_inc`), read by neighbor hrtimers (`atomic64_read`). Lock-free cross-core.
- `peer_cpu[2]` / `peer_last_seen[2]` / `peer_miss[2]` / `peer_state[2]` — this core's **local** verdict about its 2 monitored peers (prev/next). **Single writer: this core's hrtimer only**; procfs reads via `READ_ONCE`.
- `reported_state` — aggregation cache written only by the report workqueue (process context, single serialized work item), read via `READ/WRITE_ONCE`.

Key ownership rule (why there are no races with two monitors per core): each monitor writes only its **own** `peer_*` slots and **never** writes the target's data. A core's externally-visible status is derived at read time by aggregation (`ipi_monitor_aggregate`), taking the worst state / max miss across all its monitors.

### hrtimer callback (`ipi_monitor_tick`, hardirq context, pinned core)

Each cycle:
1. `atomic64_inc(own heartbeat_counter)`.
2. Compute `prev_online(me)` and `next_online(me)` from `cpu_online_mask` (dedup when prev==next, e.g. 2 cores online).
3. For each peer: if `peer_cpu[slot]` changed (hotplug), reset the slot's snapshot and `continue` (skip grading this tick, avoiding a false miss on the first snapshot); otherwise compare `cur != peer_last_seen` → `OK`/`miss++` → grade `STALLED`/`UNRESPONSIVE`.
4. On transition: `panic()` immediately if `UNRESPONSIVE` && `panic_on_unresponsive`; otherwise `schedule_work()` to defer logging.
5. `hrtimer_forward_now()` + `HRTIMER_RESTART`.

Hardirq constraints: no sleeping, no blocking, no `printk` (only `panic`). `atomic64_*`, `smp_processor_id()`, `schedule_work()` are all safe here.

Progress is detected with `!=` (not `>`), robust to counter wrap.

### Why hardirq hrtimer (not IPI, not thread, not timer_list)

The prior design drove monitoring from a kthread + `smp_call_function_single_async()`; it failed if the monitor thread was starved, and had a single monitor point of failure. The hrtimer self-heartbeat is equivalent to IPI for L2/L4 detection (both PPI and SGI are gated by `PSTATE.I`), while removing the scheduling dependency. A `timer_list` (softirq) is rejected because softirq can be deferred under extreme load.

### CPU hotplug

- `cpuhp_setup_state(CPUHP_AP_ONLINE_DYN, "ipi_monitor", online, offline)` with `invoke=true` so already-online CPUs get the online callback at load.
- `ipi_monitor_cpu_online(cpu)`: resets the core's state, then `hrtimer_init` + `hrtimer_start` **on that core**. PINNED timers must be initialized/started on their target CPU — the cpuhp AP-state callback is guaranteed to run there (`cpuhp_invoke_ap_callback`, `kernel/cpu.c`).
- `ipi_monitor_cpu_offline(cpu)`: `hrtimer_cancel` (pinned timers are NOT migrated on hotplug; must cancel explicitly).
- The monitor ring is **recomputed every tick** from `cpu_online_mask`; no explicit neighbor table. Peer identity change triggers snapshot reset.

### procfs interface

`/proc/ipi_monitor` (read-only `0444`), via `seq_file` (`single_open`/`seq_read`): per-CPU table `CPU / STATE / COUNTER / MISS` where `STATE`/`MISS` are aggregated from all monitors, plus a config summary line.

## Module parameters

| Parameter | Default | Notes |
|---|---|---|
| `check_interval_ms` | 1000 | Clamped to a minimum of 10 |
| `stall_threshold` | 3 | Consecutive misses to mark `STALLED` |
| `unresponsive_threshold` | 10 | Consecutive misses to mark `UNRESPONSIVE` (clamped ≥ `stall_threshold`) |
| `panic_on_unresponsive` | 0 | `panic()` when a core becomes `UNRESPONSIVE` |
| `monitor_enabled` | 1 | Start monitoring at load |

(The old `monitor_cpu` parameter no longer exists — there is no single monitor core.)
