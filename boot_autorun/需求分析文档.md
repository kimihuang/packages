# 启动各阶段自动运行框架需求分析

## 一、背景与问题

### 1.1 当前痛点

```
传统流程:
┌─────────┐    ┌─────────┐    ┌─────────┐
│  任务A   │    │  任务B   │    │  任务C   │
│ 改代码   │ → │ 制作版本 │ → │ 烧录测试 │
└─────────┘    └─────────┘    └─────────┘
     ↑              ↑             ↑
  每个任务都要重复此流程，耗时且易出错
```

| 问题项 | 影响 |
|--------|------|
| 每个任务需改代码、编译、烧录 | 开发效率低 |
| 版本管理混乱 | 难以追溯测试配置 |
| 人工干预多 | 容易引入人为错误 |
| 无法灵活组合任务 | 测试覆盖受限 |

### 1.2 目标愿景

```
期望流程:
┌──────────┐     ┌──────────────┐     ┌────────────────┐
│ JSON配置  │ --> │ PC脚本转换    │ --> │ 烧录配置到内存   │
│ (任务列表)│     │ (生成二进制)   │     │ (SRAM/DDR)     │
└──────────┘     └──────────────┘     └────────────────┘
                                                      ↓
              ┌──────────────────────────────────────────────┐
              │         启动各阶段自动执行                      │
              │  BL1 → BL31 → RT-Thread → U-Boot → Linux     │
              │         读取同一配置，各司其职                   │
              └──────────────────────────────────────────────┘
```

### 2.2 各阶段内存分配策略

| 启动阶段 | 可用内存 | 配置地址 | 说明 |
|----------|----------|----------|------|
| **BL1** | SRAM (有限) | `0xFFFF_0000` (SRAM顶部) | 尽早执行，配置需紧凑 |
| **BL31** | SRAM/Secure DDR | `0x_SRAM_BASE + offset` | TrustZone环境 |
| **RT-Thread** | DDR | `0xDDR_CONFIG_BASE` | 可用空间充足 |
| **U-Boot** | DDR | `0xDDR_CONFIG_BASE + offset` | 与RT-Thread共享或独立 |
| **Linux** | DDR (保留内存) | `reserved-memory` | 通过DTB或cmdline传递地址 |

### 3.2 二进制配置数据结构 (Target侧)

```c
/**
 * @file autorun_config.h
 * @brief 自动运行框架配置数据结构定义
 *
 * 设计原则:
 * 1. 结构体紧凑，减少内存占用 (尤其BL1阶段)
 * 2. 使用固定长度数组，避免动态内存
 * 3. 魔数+版本号用于校验和向前兼容
 * 4. 所有字段使用定长类型，确保跨平台一致
 */

#ifndef AUTORUN_CONFIG_H
#define AUTORUN_CONFIG_H

#include <stdint.h>

#ifdef __cplusplus
extern "C" {
#endif

/* ========== 魔数和版本 ========== */
#define AUTORUN_MAGIC           0xA55A5AA5UL  /* 魔数: 用于识别有效配置 */
#define AUTORUN_VERSION_MAJOR   1
#define AUTORUN_VERSION_MINOR   0
#define AUTORUN_VERSION_PATCH   0

/* ========== 常量定义 ========== */
#define AUTORUN_TASK_NAME_MAX_LEN     32   /* 任务名称最大长度 */
#define AUTORUN_CMD_MAX_LEN           128  /* shell命令最大长度 */
#define AUTORUN_PATTERN_MAX_LEN       64   /* 匹配模式最大长度 */
#define AUTORUN_STAGE_NAME_MAX_LEN    16   /* 阶段名称最大长度 */
#define AUTORUN_MAX_TASKS_PER_STAGE   16   /* 每阶段最大任务数 */
#define AUTORUN_MAX_STAGES            5    /* 最大支持阶段数 */

/* ========== 结果类型枚举 ========== */
typedef enum __attribute__((packed)) {
    EXPECT_TYPE_RETURN_CODE = 0,    /* 期望返回码 */
    EXPECT_TYPE_STRING_MATCH = 1,   /* 字符串匹配 */
    EXPECT_TYPE_REGEX = 2,          /* 正则表达式匹配 */
    EXPECT_TYPE_CHECKSUM = 3,       /* 校验和验证 */
    EXPECT_TYPE_JSON_OUTPUT = 4,    /* JSON输出解析 */
    EXPECT_TYPE_RANGE = 5,          /* 数值范围检查 */
} expect_type_t;

/* ========== 校验算法枚举 ========== */
typedef enum __attribute__((packed)) {
    CHECKSUM_ALG_CRC32 = 0,
    CHECKSUM_ALG_MD5 = 1,
    CHECKSUM_ALG_SHA256 = 2
} checksum_alg_t;

/* ========== 期望结果结构体 (联合体节省空间) ========== */
typedef struct {
    expect_type_t type;                    /* 结果类型 */
    union {
        struct {
            int32_t expected_code;         /* 期望返回码 */
        } return_code;
        struct {
            char pattern[PATTERN_MAX_LEN]; /* 匹配模式 */
        } string_match;
        struct {
            char pattern[PATTERN_MAX_LEN]; /* 正则表达式 */
        } regex;
        struct {
            checksum_alg_t algorithm;      /* 校验算法 */
            uint32_t expected_value;       /* 期望校验值 */
        } checksum;
        struct {
            char keys[4][24];              /* 要检查的JSON key (最多4个) */
        } json_output;
        struct {
            int32_t min_val;               /* 最小值 */
            int32_t max_val;               /* 最大值 */
        } range;
    };
} expected_result_t;

/* ========== 单个任务配置结构体 ========== */
typedef struct {
    uint32_t            id;                          /* 任务ID (全局唯一) */
    char                name[TASK_NAME_MAX_LEN];     /* 任务名称 */
    char                command[CMD_MAX_LEN];        /* shell命令 */
    expected_result_t   expected_result;             /* 期望结果 */
    uint32_t            timeout_ms;                  /* 超时时间(毫秒) */
    uint8_t             critical : 1;                /* 是否关键任务(失败则终止) */
    uint8_t             enabled : 1;                 /* 是否启用 */
    uint8_t             reserved : 6;                /* 保留位 */
    uint8_t             retry_count;                 /* 失败重试次数 */
    uint32_t            retry_delay_ms;              /* 重试间隔(毫秒) */
} task_config_t;

/* ========== 单个阶段配置结构体 ========== */
typedef struct {
    char                stage_name[STAGE_NAME_MAX_LEN]; /* 阶段名称 */
    uint8_t             enabled;                        /* 是否启用本阶段 */
    uint8_t             task_count;                     /* 任务数量 */
    uint8_t             reserved[2];                    /* 对齐填充 */
    task_config_t       tasks[MAX_TASKS_PER_STAGE];     /* 任务数组 */
} stage_config_t;

/* ========== 全局配置结构体 ========== */
typedef struct {
    uint32_t        magic;                              /* 魔数 */
    uint16_t        version_major;                      /* 主版本号 */
    uint16_t        version_minor;                      /* 次版本号 */
    uint32_t        config_size;                        /* 整个配置结构大小(字节) */
    uint32_t        crc32;                              /* 配置CRC校验值 */

    /* 全局控制参数 */
    uint8_t         log_level;                          /* 日志级别: 0=off, 1=err, 2=warn, 3=info, 4=debug */
    uint8_t         continue_on_error;                  /* 出错是否继续: 0=停止, 1=继续 */
    uint16_t        global_timeout_s;                   /* 全局超时(秒), 0=无限制 */

    /* 结果输出区域 */
    uint32_t        result_output_addr;                 /* 结果输出内存地址 */
    uint32_t        result_max_size;                    /* 结果区域最大大小 */

    /* 各阶段配置 */
    uint32_t        stage_count;                        /* 启用的阶段数量 */
    stage_config_t  stages[MAX_STAGES];                 /* 各阶段配置 */
} autorun_config_t;

/* ========== 任务执行结果结构体 (运行时写入) ========== */
typedef enum __attribute__((packed)) {
    TASK_STATUS_PENDING = 0,     /* 待执行 */
    TASK_STATUS_RUNNING = 1,     /* 执行中 */
    TASK_STATUS_SUCCESS = 2,     /* 成功 */
    TASK_STATUS_FAILED = 3,      /* 失败 */
    TASK_STATUS_TIMEOUT = 4,     /* 超时 */
    TASK_STATUS_SKIPPED = 5      /* 跳过 */
} task_status_t;

typedef struct {
    uint32_t        task_id;                    /* 任务ID */
    task_status_t   status;                     /* 执行状态 */
    int32_t         return_code;                /* 返回码 */
    uint32_t        actual_timeout_ms;          /* 实际耗时(毫秒) */
    char            output_summary[128];        /* 输出摘要 (前128字符) */
    uint32_t        timestamp_start;            /* 开始时间戳 */
    uint32_t        timestamp_end;              /* 结束时间戳 */
} task_result_t;

typedef struct {
    uint32_t        magic;                      /* 结果魔数: 0xBEEFBEEF */
    uint32_t        total_tasks;                /* 总任务数 */
    uint32_t        passed_count;               /* 通过数 */
    uint32_t        failed_count;               /* 失败数 */
    uint32_t        skipped_count;              /* 跳过数 */
    uint32_t        overall_status;             /* 总体状态: 0=pass, 1=fail */
    char            last_failed_task[TASK_NAME_MAX_LEN]; /* 最后失败的任务名 */
    task_result_t   results[];                  /* 变长数组: 各任务结果 */
} autorun_result_t;

#ifdef __cplusplus
}
#endif

#endif /* AUTORUN_CONFIG_H */
```

### 3.3 内存布局与大小计算

```
配置结构体内存占用估算:

autorun_config_t:
├── 头部 (magic + version + size + crc)        = 16 bytes
├── 全局配置 (log_level + timeout + result...)  = 20 bytes
├── stage_count                                 = 4 bytes
├── stages[5] (5个阶段):
│   ├── 每个stage头部                           = 24 bytes
│   └── tasks[16] (每阶段最多16个任务):
│       ├── 每个task固定部分                    = 176 bytes
│       └── expected_result (联合体, 最大)      ≈ 112 bytes
│       └── 每个task总计                         ≈ 288 bytes
│   └── 每个stage总计                            ≈ 4632 bytes
└── 总计                                        ≈ 23.2 KB (最坏情况)

优化后的典型配置 (每阶段平均4个任务):
└── 总计                                        ≈ 6-8 KB
```

```python
# config_generator.py 核心接口

class ConfigGenerator:
    """
    JSON配置 → 二进制配置转换器

    功能:
    1. 解析JSON配置文件
    2. 校验配置合法性
    3. 生成二进制配置数据
    4. 计算CRC32校验值
    5. 支持分阶段输出 (可单独提取某阶段的配置)

    def __init__(self, json_path: str):
        """加载JSON配置文件"""

    def validate(self) -> List[str]:
        """校验配置, 返回错误/警告列表"""

    def generate_binary(self) -> bytes:

    def get_stage_binary(self, stage_name: str,

        """获取指定阶段的二进制配置及其偏移量"""

    def calculate_crc32(self, data: bytes) -> uint32:
        """计算CRC32校验值"""

    def output_info(self) -> dict:
        """输出配置统计信息 (任务数、预估大小等)"""
```

### 5.2 核心引擎伪代码

```c
/**
 * @file autorun_core.c
 * @brief 自动运行框架核心引擎
 */

#include "autorun_framework.h"

/* ========== 全局状态 ========== */
static autorun_config_t *g_config = NULL;
static autorun_result_t *g_result = NULL;
static const autorun_platform_ops_t *g_ops = NULL;

/**
 * @brief 初始化框架
 *
 * @param config_addr  配置数据在内存中的地址
 * @param result_addr  结果输出区域的地址
 * @param ops          平台相关操作函数表
 * @return int         0=成功, 负值=错误码
 */
int autorun_init(uint32_t config_addr, uint32_t result_addr,
                 const autorun_platform_ops_t *ops)
{
    /* 1. 校验魔数和版本 */
    g_config = (autorun_config_t *)config_addr;
    if (g_config->magic != AUTORUN_MAGIC) {
        return -ERR_INVALID_MAGIC;
    }

    /* 2. CRC32校验 */
    uint32_t calc_crc = crc32_calc((uint8_t *)g_config,
                                    g_config->config_size);
    if (calc_crc != g_config->crc32) {
        return -ERR_CRC_MISMATCH;
    }

    /* 3. 初始化结果区域 */
    g_result = (autorun_result_t *)result_addr;
    memset(g_result, 0, sizeof(autorun_result_t));
    g_result->magic = RESULT_MAGIC;

    /* 4. 保存平台操作函数 */
    g_ops = ops;

    return 0;
}

/**
 * @brief 执行当前阶段的所有任务
 *
 * @param stage_name  当前阶段名称 (如 "bl1", "rtthread")
 * @return int        0=全部通过, 负值=有失败
 */
int autorun_run_stage(const char *stage_name)
{
    stage_config_t *stage = NULL;

    /* 1. 查找当前阶段的配置 */
    for (uint32_t i = 0; i < g_config->stage_count; i++) {
        if (strcmp(g_config->stages[i].stage_name, stage_name) == 0) {
            stage = &g_config->stages[i];
            break;
        }
    }

    if (!stage || !stage->enabled) {
        return 0;  /* 阶段未配置或未启用, 视为通过 */
    }

    g_ops->log_printf(LOG_INFO, "=== Stage [%s] started ===", stage_name);

    /* 2. 遍历执行每个任务 */
    for (uint8_t i = 0; i < stage->task_count; i++) {
        task_config_t *task = &stage->tasks[i];
        task_result_t *result = &g_result->results[g_result->total_tasks];

        if (!task->enabled) {
            result->status = TASK_STATUS_SKIPPED;
            g_result->skipped_count++;
            continue;
        }

        /* 执行单个任务 (含重试逻辑) */
        int ret = execute_single_task(task, result);

        g_result->total_tasks++;

        if (ret != 0 && task->critical) {
            g_ops->log_printf(LOG_ERROR,
                "Critical task [%s] failed, aborting!", task->name);
            g_result->overall_status = 1;
            strcpy(g_result->last_failed_task, task->name);
            return -ERR_CRITICAL_TASK_FAILED;
        }

        if (!g_config->continue_on_error && ret != 0) {
            g_result->overall_status = 1;
            return ret;
        }
    }

    g_ops->log_printf(LOG_INFO, "=== Stage [%s] completed ===", stage_name);
    return 0;
}

/**
 * @brief 执行单个任务 (内部函数)
 */
static int execute_single_task(task_config_t *task, task_result_t *result)
{
    char output_buf[OUTPUT_BUF_SIZE];
    int retry = 0;

    result->task_id = task->id;
    result->timestamp_start = g_ops->get_timestamp();

    do {
        result->status = TASK_STATUS_RUNNING;
        g_ops->log_printf(LOG_INFO, "Running task [%d]: %s",
                         task->id, task->name);

        /* 调用平台的shell命令执行 */
        int ret = g_ops->execute_command(task->command, output_buf,
                                         sizeof(output_buf),
                                         task->timeout_ms);

        result->return_code = ret;

        /* 检查结果是否符合预期 */
        if (check_expected_result(&task->expected_result, ret,
                                   output_buf)) {
            result->status = TASK_STATUS_SUCCESS;
            g_result->passed_count++;

            /* 记录输出摘要 */
            strncpy(result->output_summary, output_buf,
                    sizeof(result->output_summary) - 1);

            g_ops->log_printf(LOG_INFO,
                "Task [%s] PASSED (retry %d)", task->name, retry);
            break;
        } else {
            retry++;
            g_ops->log_printf(LOG_WARN,
                "Task [%s] FAILED (attempt %d/%d)",
                task->name, retry, task->retry_count + 1);

            if (retry <= task->retry_count) {
                g_ops->delay_ms(task->retry_delay_ms);
            }
        }
    } while (retry <= task->retry_count);

    if (result->status != TASK_STATUS_SUCCESS) {
        result->status = (retry > task->retry_count) ?
                         TASK_STATUS_FAILED : TASK_STATUS_TIMEOUT;
        g_result->failed_count++;
    }

    result->timestamp_end = g_ops->get_timestamp();
    result->actual_timeout_ms = result->timestamp_end -
                                result->timestamp_start;

    return (result->status == TASK_STATUS_SUCCESS) ? 0 : -1;
}
```

```c
/**
 * @file autorun_platform.h
 * @brief 平台适配层接口定义
 *
 * 每个启动阶段需要实现此接口, 以适配各自的:
 * - 日志输出机制 (printf / LOG_INFO / pr_info)
 * - shell命令执行方式 (system() / popen() / 自定义)
 * - 时间戳获取 (tick count / ktime_get)
 * - 延时函数 (udelay / msleep)
 */

#ifndef AUTORUN_PLATFORM_H
#define AUTORUN_PLATFORM_H

typedef struct {
    /**
     * @brief 日志输出
     * @param level  日志级别
     * @param fmt    格式字符串
     */
    void (*log_printf)(int level, const char *fmt, ...);

    /**
     * @brief 执行shell命令
     * @param command     命令字符串
     * @param output      输出缓冲区
     * @param output_size 缓冲区大小
     * @param timeout_ms  超时时间
     * @return int        命令返回码
     */
    int (*execute_command)(const char *command, char *output,
                           size_t output_size, uint32_t timeout_ms);

    /**
     * @brief 获取当前时间戳 (毫秒)
     * @return uint32_t 时间戳
     */
    uint32_t (*get_timestamp)(void);

    /**
     * @brief 毫秒级延时
     * @param ms 延时毫秒数
     */
    void (*delay_ms)(uint32_t ms);

    /**
     * @brief 内存拷贝 (可能需要特殊处理Cache一致性)
     */
    void *(*memcpy)(void *dest, const void *src, size_t n);

    /**
     * @brief 内存清零
     */
    void (*memset)(void *s, int c, size_t n);

} autorun_platform_ops_t;

#endif /* AUTORUN_PLATFORM_H */
```

```c
/* ==================== BL1 适配层 (最小化实现) ==================== */
/* bl1_port.c - BL1环境资源极其有限, 只提供基本功能 */

#ifdef CONFIG_AUTORUN_BL1
#include <uart.h>  /* 假设BL1有简单的UART驱动 */

static void bl1_log(int level, const char *fmt, ...)
{
    va_list args;
    va_start(args, fmt);
    uart_vprintf(fmt, args);  /* 直接输出到UART */
    va_end(args);
}

static int bl1_execute_command(const char *cmd, char *output,
                                size_t out_sz, uint32_t timeout)
{
    /* BL1的shell实现通常很简单, 可能只支持预注册的命令 */
    return bl1_shell_execute(cmd, output, out_sz, timeout);
}

static uint32_t bl1_get_timestamp(void)
{
    return *(volatile uint32_t *)(TIMER_BASE);  /* 通用定时器 */
}

static void bl1_delay_ms(uint32_t ms)
{
    volatile uint32_t end = bl1_get_timestamp() + ms;
    while (bl1_get_timestamp() < end);
}

const autorun_platform_ops_t bl1_autorun_ops = {
    .log_printf = bl1_log,
    .execute_command = bl1_execute_command,
    .get_timestamp = bl1_get_timestamp,
    .delay_ms = bl1_delay_ms,
    .memcpy = memcpy,
    .memset = memset,
};

int bl1_run_autorun(void)
{
    /* BL1配置地址: SRAM顶部 (由链接脚本或寄存器指定) */
    #define BL1_CONFIG_ADDR  0xFFFF0000
    #define BL1_RESULT_ADDR  0xFFFF8000

    return autorun_init(BL1_CONFIG_ADDR, BL1_RESULT_ADDR, &bl1_autorun_ops)
        || autorun_run_stage("bl1");
}

/* ==================== RT-Thread 适配层 ==================== */
/* rtthread_port.c - 使用RT-Thread丰富的API */

#ifdef CONFIG_AUTORUN_RTTHREAD
#include <rtthread.h>

static void rtthread_log(int level, const char *fmt, ...)
{
    switch (level) {
        case LOG_ERROR: rt_kprintf("[ERR] "); break;
        case LOG_WARN:  rt_kprintf("[WRN] "); break;
        case LOG_INFO:  rt_kprintf("[INF] "); break;
        default:       rt_kprintf("[DBG] "); break;
    }
    va_list args;
    va_start(args, fmt);
    rt_kprintf(fmt, args);  /* RT-Thread的rt_kprintf */
    va_end(args);
}

static int rtthread_execute_command(const char *cmd, char *output,
                                     size_t out_sz, uint32_t timeout)
{
    /* 使用RT-Thread的finsh/msh system接口 */
    return rt_system(cmd, output, out_sz, timeout);
}

static uint32_t rtthread_get_timestamp(void)
{
    return rt_tick_get() * (1000 / RT_TICK_PER_SECOND);
}

static void rtthread_delay_ms(uint32_t ms)
{
    rt_thread_mdelay(ms);
}

const autorun_platform_ops_t rtthread_autorun_ops = {
    .log_printf = rtthread_log,
    .execute_command = rtthread_execute_command,
    .get_timestamp = rtthread_get_timestamp,
    .delay_ms = rtthread_delay_ms,
    .memcpy = rt_memcpy,
    .memset = rt_memset,
};

int rtthread_run_autorun(void)
{
    /* RT-Thread配置地址: DDR中固定位置 */
    #define RTT_CONFIG_ADDR  0x10000000
    #define RTT_RESULT_ADDR  0x10010000

    if (autorun_init(RTT_CONFIG_ADDR, RTT_RESULT_ADDR, &rtthread_autorun_ops) != 0) {
        rt_kprintf("Autorun init failed!\n");
        return -1;
    }

    return autorun_run_stage("rtthread");
}
#endif


/* ==================== Linux 适配层 (用户态) ==================== */
/* linux_port.c - 作为独立的用户态程序运行 */

#ifdef CONFIG_AUTORUN_LINUX
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <sys/time.h>

static void linux_log(int level, const char *fmt, ...)
{
    const char *prefix[] = {"", "ERROR: ", "WARN: ", "INFO: ", "DEBUG: "};
    fprintf(stderr, "%s", prefix[level]);
    va_list args;
    va_start(args, fmt);
    vfprintf(stderr, fmt, args);
    va_end(args);
}

static int linux_execute_command(const char *cmd, char *output,
                                  size_t out_sz, uint32_t timeout)
{
    /* 使用popen执行命令并捕获输出 */
    FILE *fp = popen(cmd, "r");
    if (!fp) return -1;

    size_t total = 0;
    while (!feof(fp) && total < out_sz - 1) {
        size_t n = fread(output + total, 1, out_sz - total - 1, fp);
        if (n <= 0) break;
        total += n;
    }
    output[total] = '\0';

    int status = pclose(fp);
    return WIFEXITED(status) ? WEXITSTATUS(status) : -1;
}

static uint32_t linux_get_timestamp(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (uint32_t)(ts.tv_sec * 1000 + ts.tv_nsec / 1000000);
}

static void linux_delay_ms(uint32_t ms)
{
    struct timespec req = { .tv_sec = ms / 1000, .tv_nsec = (ms % 1000) * 1000000 };
    nanosleep(&req, NULL);
}

const autorun_platform_ops_t linux_autorun_ops = {
    .log_printf = linux_log,
    .execute_command = linux_execute_command,
    .get_timestamp = linux_get_timestamp,
    .delay_ms = linux_delay_ms,
    .memcpy = memcpy,
    .memset = memset,
};

/* Linux入口: 从命令行或设备树获取配置地址 */
int main(int argc, char *argv[])
{
    uint32_t config_addr = DEFAULT_LINUX_CONFIG_ADDR;
    uint32_t result_addr = DEFAULT_LINUX_RESULT_ADDR;

    /* 支持命令行参数覆盖默认地址 */
    if (argc >= 3) {
        config_addr = strtoul(argv[1], NULL, 0);
        result_addr = strtoul(argv[2], NULL, 0);
    }

    /* 将物理地址映射到用户空间 (需要mmap /dev/mem) */
    void *cfg_map = mmap_phys(config_addr, sizeof(autorun_config_t));
    void *res_map = mmap_phys(result_addr, MAX_RESULT_SIZE);

    if (!cfg_map || !res_map) {
        fprintf(stderr, "Memory map failed\n");
        return -1;
    }

    if (autorun_init((uint32_t)cfg_map, (uint32_t)res_map,
                     &linux_autorun_ops) != 0) {
        fprintf(stderr, "Autorun init failed\n");
        return -1;
    }

    int ret = autorun_run_stage("linux");

    /* 输出最终结果摘要 */
    printf("\n========== AUTORUN SUMMARY ==========\n");
    printf("Total: %d | Passed: %d | Failed: %d | Skipped: %d\n",
           g_result->total_tasks, g_result->passed_count,
           g_result->failed_count, g_result->skipped_count);
    printf("Overall: %s\n",
           g_result->overall_status ? "FAIL" : "PASS");
    printf("=====================================\n");

    munmap(cfg_map, sizeof(autorun_config_t));
    munmap(res_map, MAX_RESULT_SIZE);

    return ret;
}
#endif
```

### 6.1 完整启动流程

```
Power On
    ↓
[BL1 Stage]
    │
    ├─ 1. BL1初始化硬件 (DDR/时钟/串口)
    ├─ 2. 检测到配置数据 @ SRAM_CONFIG_ADDR
    ├─ 3. autorun_init() → 校验魔数+CRC
    ├─ 4. autorun_run_stage("bl1")
    │   ├─ Task 1: ddr_init_test → [PASS]
    │   ├─ Task 2: clk_verify → [PASS]
    │   └─ Task N: ... → [PASS/FAIL]
    ├─ 5. 写入BL1阶段结果到 RESULT_ADDR
    │
    ↓ (跳转到BL31)
[BL31 Stage]
    │
    ├─ 1. BL31初始化 (PSCI/SMC/安全配置)
    ├─ 2. 读取同一配置 (不同偏移或地址)
    ├─ 3. autorun_run_stage("bl31")
    │   └─ ...
    ├─ 4. 写入BL31阶段结果
    │
    ↓ (跳转到RT-Thread/U-Boot/Linux)
[RT-Thread / U-Boot / Linux Stages]
    │
    └─ 类似流程...
    │
    ↓
[所有阶段完成]
    ↓
[PC侧读取结果]
    ├─ download_tool.read_result()
    ├─ result_parser.generate_report()
    └─ 输出: HTML/PDF/Console 报告
```

### 6.2 错误处理策略

```
任务执行决策树:

execute_task(task)
    │
    ├─ 任务启用?
    │   └─ No → SKIPPED
    │
    ├─ 执行命令
    │   ├─ 超时 → TIMEOUT
    │   └─ 得到返回码和输出
    │
    ├─ 检查预期结果
    │   ├─ 匹配 → SUCCESS ✓
    │   └─ 不匹配 → FAILED ✗
    │
    ├─ 有重试次数?
    │   ├─ Yes → delay → 重试
    │   └─ No → 最终状态确定
    │
    └─ 关键任务?
        ├─ Yes → 中止整个阶段 (critical failure)
        └─ No → continue_on_error?
            ├─ Yes → 继续下一个任务
            └─ No → 中止整个阶段
```

## 七、关键技术与难点

### 7.1 内存一致性 (Cache Coherency)

```
问题场景:
┌──────────┐         ┌─────────────┐
│  PC侧写  │ ──────→ │  DDR Memory │ ← CPU可能Cached
│  配置数据 │  JTAG  │  (配置区域)  │
└──────────┘         └─────────────┘
                            ↓
                    CPU读取可能是旧数据 (Cache未失效)

解决方案:
1. BL1/BL31阶段 (通常无Cache或可关闭Cache):
   - 无需特殊处理

2. RT-Thread/U-Boot阶段 (可能有Cache):
   - 方案A: 配置区域设为非缓存 (MMU映射为 Device-nGnRnE)
   - 方案B: 读取前手动 Clean/Invalidate Cache
   - 方案C: 使用虚拟地址通过 uncached 映射访问

3. Linux阶段:
   - 使用 dma_alloc_coherent() 分配结果缓冲区
   - 或通过 ioremap_wc() 映射配置区域
```

### 7.2 内存地址传递机制

| 方法 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| **硬编码地址** | BL1/早期阶段 | 简单直接 | 不灵活 |
| **链接脚本符号** | 编译期确定 | 可移植性好 | 需重新编译才能改 |
| **寄存器传递** | BL1→BL31 | 硬件级可靠 | 需要专用寄存器 |
| **Device Tree** | U-Boot/Linux | 标准化 | 需要DT支持 |
| **cmdline/bootargs** | Linux | 易于修改 | 大小限制 |
| **共享内存约定** | 所有阶段 | 统一方案 | 需要文档约束 |

**推荐方案**: 组合使用
- BL1/BL31: 硬编码 + 链接脚本符号
- RT-Thread/U-Boot: 共享内存约定 (固定地址宏定义)
- Linux: Device Tree `reserved-memory` + cmdline 参数

### 7.3 各阶段Shell能力差异

| 阶段 | Shell类型 | 能力限制 | 适配建议 |
|------|-----------|----------|----------|
| **BL1** | 最小Shell | 命令集有限, 无管道/重定向 | 预注册命令表, 不支持复杂语法 |
| **BL31** | SMC调用 | 通常无交互式Shell | 通过SMC接口执行预设操作 |
| **RT-Thread** | finsh/msh | 支持基本命令, 有限管道 | 可扩展自定义命令 |
| **U-Boot** | 完整Shell | 支持变量/条件/循环 | 能力最强, 几乎无限制 |
| **Linux** | Bash/Sh | 完整POSIX Shell | 可使用任意Linux命令 |

## 八、配置数据保护与安全

### 8.1 完整性保护

```
保护层次:
┌─────────────────────────────────────────┐
│ Level 1: Magic Number (4 bytes)         │ ← 快速识别有效配置
├─────────────────────────────────────────┤
│ Level 2: Version Check (Major.Minor)    │ ← 兼容性检查
├─────────────────────────────────────────┤
│ Level 3: CRC32 of entire structure      │ ← 数据完整性
├─────────────────────────────────────────┤
│ Level 4: Optional Signature (RSA/ECDSA) │ ← 防篡改 (可选)
└─────────────────────────────────────────┘
```

### 8.2 安全考虑 (可选增强)

| 威胁 | 对策 |
|------|------|
| 配置被篡改 | RSA签名验证 (BL31及以后阶段) |
| 恶意命令注入 | 命令白名单机制 |
| 结果被伪造 | 结果区域写保护 (仅框架可写) |
| DOS (超长执行) | 强制全局超时 + per-task超时 |
